SMASHSYNC / SMASH AI - RUN INSTRUCTIONS
=======================================

NORMAL USE
----------
Use SmashAI.bat for normal use.

Launch-SmashAI.bat is only the old/manual launcher for troubleshooting, bridge
tests, or development. You normally do not need it anymore.

FIRST-TIME SETUP
----------------
1. Put your working portable folder beside Ryujinx.exe.
2. Run Install-SmashAI-NRO.bat once.
3. Run Install-SmashAI-ML.bat once.
4. Run SmashAI.bat.
5. In Setup / Status, click Check ML Device.
   AMD/Intel systems should normally report DirectML.

TRAIN AN AI
-----------
1. Run SmashAI.bat.
2. Open the Train tab.
3. Choose a model folder.
4. Choose Parallel Ryujinx workers. Start with 1 for a basic test, then try 2-3.
   Move toward 5 only if the reported aggregate simulated FPS keeps increasing.
5. Leave Resume checkpoint blank unless you want a specific checkpoint.
   If latest.pt already exists in that model folder, training auto-resumes.
6. Click Start / Resume Training.
7. Ryujinx worker windows open. For every visible worker:
   - enter Training Mode,
   - choose the SAME character being trained as P1,
   - choose an active CPU opponent,
   - choose a stage,
   - enter the match.
   CPU character/level and stage may differ between workers.
8. Each ready worker can auto-hide after entering the match.
9. One central PPO learner combines all worker rollouts into the same model.

During training, the Output box reports:
- episode number and outcome,
- PPO update number,
- environment steps,
- simulated frames per second,
- speed relative to normal 60 Hz,
- rolling recent win rate,
- recent mean reward,
- policy/value losses,
- checkpoint saves.

Training uses exact SSBU frame stepping, automatic Training Mode resets,
unbounded host pacing, muted audio, and host-presentation suppression. Hidden
workers still execute SSBU/GPU work required by the game, but they skip the
final copy/present to the visible Ryujinx window. The game can therefore
simulate faster than real time while preserving exact virtual frame boundaries.

The UI reports sim_fps and speed. A speed of 4.0x means four seconds of SSBU
virtual gameplay are being simulated per one second of wall-clock time. With
multiple workers, aggregate_speed is the combined throughput across all workers.

Use Show Random Worker if you want to view one launched training instance.
That worker's host presentation is temporarily re-enabled, but its unbounded
accelerated pacing remains active. Use Hide Worker Windows to suppress
presentation and hide all training windows again.

HOW TO TELL IF IT IS LEARNING / TRAINED
---------------------------------------
Training is not a binary on/off state. Do not judge it from policy loss alone.

During training, watch:
- sim_fps / speed: throughput, not skill,
- mean_return_50: recent reward trend,
- win50: recent decisive win rate against the current training opponent mix.

For a cleaner skill check, stop training and click Evaluate model.pt (20) in
the Train tab. Enter Training Mode with a CPU/stage you want to use as a fixed
benchmark. Evaluation uses deterministic actions for 20 episodes and prints:
- wins,
- losses,
- draws/timeouts,
- decisive win rate,
- mean return.

For meaningful comparison over time, reuse the same benchmark CPU character,
CPU level, stage, and episode frame limit. Also test held-out opponents/stages
that were not used heavily for training.

MODEL FILES
-----------
latest.pt
  Full checkpoint including optimizer state. Use this to resume training.

model.pt
  Smaller shareable policy weights. This is the normal file to send to another
  SmashSync user for Play with AI.

snapshot_XXXXXX.pt
  Older policy snapshots. These are also useful for evaluation and future
  self-play.

model.json
  Metadata and latest training counters.

PLAY AGAINST A TRAINED AI
-------------------------
1. Run SmashAI.bat.
2. Open Play with AI.
3. Select model.pt.
4. Choose whether the AI controls P1, P2, or P3.
5. Click Start Play with AI.
6. Navigate SSBU normally and select characters/stage normally.
7. Start the match.

The AI does not take over during menus. It takes over the selected player only
after an actual match begins, and releases control again when the match ends.

For P2/P3, keep that Ryujinx controller slot configured so the player can join
character select. You can use the keyboard/controller to select the AI's
character, then the model takes over once the match starts.

SHARING WITH A FRIEND
---------------------
Send:
- the SmashSync/Ryujinx build,
- the desired model.pt,
- RUN INSTRUCTIONS.txt.

Do not distribute game files, console keys, or firmware from your portable
folder. Your friend should use their own legally obtained SSBU installation,
keys, firmware, and configuration, then install the bundled SmashAI NRO.

Your friend currently needs Python plus the ML dependencies installed by
Install-SmashAI-ML.bat. A later ONNX/integrated inference build is planned so
Play with AI will not need Python or PyTorch.

CHARACTERS, STAGES, AND PLAYER SLOTS
------------------------------------
P1/P2/P3 do NOT need separate neural-network experts. The policy state encoder
is self-relative, so the same model can control any supported player slot.

Character expertise is different. For the current training system, treat one
model folder as one fighter expert. All parallel workers for that model must use
the same P1 fighter. It may run on another fighter, but quality is not
guaranteed. A later universal policy can train across fighter IDs.

Stage generalization depends on training diversity. A practical current setup
is to put the same trainee on several workers but use different legal stages
and different CPU opponents/levels. This teaches one fighter expert across a
broader distribution. Richer explicit stage-geometry features are planned.

CPU opponents are only the first curriculum. Saved snapshot opponents and
self-play are planned so the AI does not merely specialize against Nintendo's
CPU behavior.

TROUBLESHOOTING
---------------
If SmashAI.bat reports the bridge is offline:
- make sure Ryujinx was launched through the SmashAI UI or Launch-SmashAI.bat,
- make sure the bridge port is 24872 unless intentionally changed.

If exporter state is unavailable:
- enter an SSBU match,
- verify libsmash_ai_state.nro is installed,
- do not install Smashline for this build.

If exact stepping gets stuck:
- stop the trainer. The host watchdog releases the frame gate after trainer
  silence, and the UI also clears controller overrides when stopped.
